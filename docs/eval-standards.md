# 评测标准设计（四栏：输出 / 团队增益 / 控制 / 生存）

> 用户定位：**强度量级评判与场景适配**，不追求极限轴复现。
> 团队增益、控制能力、生存能力**各自单开栏**——它们与输出画像并列，各自有独立的评测标准。
> 这些栏弹性高、场景依赖强，标准是"半定量框架 + LLM 判断"，不是纯规则打分。

---

## 0. 栏目划分

| 栏 | 回答的问题 | 量化程度 | 状态 |
|---|---|---|---|
| ① 输出栏 | 这个干员自己能打多少？打什么场景强？ | 高（DPS 画像/分场景/费效） | ✅ 已实现 |
| ② 团队增益栏 | 这个干员能让**队友**多打多少？ | 中（相对提升 % + 覆盖率） | ✅ 已实现 |
| ③ 控制栏 | 这个干员能控住敌人多久、控得多硬？ | 中（控制时长/覆盖率 + 类型分级） | ✅ 已实现 |
| ④ 生存栏 | 这个干员能扛多少？靠什么扛？ | 中高（承伤/可挨击数/秒数 + 闪避自回） | ✅ 已实现 |

**归属原则**：
- 干员自己挂的减益、自己又吃到 → 计入①输出栏（已实现：`enemyDebuff`）
- 同一个减益对**队友**的价值 → 计入②团队增益栏（不重复计入自身 DPS）
- 一切控制效果（眩晕/束缚/停顿/减速/睡眠/恐惧）→ 只进③，不进①（控制不直接转换成伤害）
- 一切"自己不被击倒"的机制 → 只进④；**给队友的**治疗/护盾/减攻 → ④ 的团队子项（与 ② 的增益区分：② 管输出提升，④ 管生存保障）

## 0.1 强度评测的关键点（用户明确，2026）

| 关键点 | 说明 | 现状 |
|---|---|---|
| **① DPS** | 输出能力，分场景画像 | ✅ 已实现（含天赋/模组/穿透/元素/爆发/陷阱） |
| **② 泛用性** | 跨场景适配广度 —— 换场景后还强不强 | ✅ 已实现（`tools/versatility.mjs` + `data/scenario-baseline.json`）|
| **③ 操作难度** | 自动/手动触发、时机窗口、站位要求、部署限制 | ✅ 已实现（`tools/difficulty.mjs`）|
| **④ 回转时间** | 首轮可用时间 / 完整周期 / 空窗 / 窗口内可开次数 | ✅ 已实现（`tools/rotation.mjs`） |
| **⑤ 生存** | 承伤/自回/闪避 | ✅ 已实现（④ 生存栏），**定位为"锦上添花但仍是关键一环"** |

### 泛用性口径（②，已实现）
可用线来自 `data/scenario-baseline.json`（全库 433 名干员 × 6 场景的输出分布）。三个可验证指标：
1. **场景覆盖**：达基本可用线（p25）/ 稳健线（p50）的场景数
2. **波动比**：最差场景 ÷ 中位场景（越低越偏科）
3. **属性衰减**：物理看 DEF 0→800、法术看 RES 0→90 的衰减百分比
分级（**不合成假精确的单一分数**）：全能型（稳健线≥5 且波动比≥0.5）/ 通用型（稳健线≥5 或全场景达基本线）/ 偏科型（基本线 3–5）/ 特化型（≤2）。

实测校准：银灰 全能型（6/6·0.54·护甲衰减52%）；**能天使 通用型（护甲衰减 95%、波动比 0.07 = 高甲短板）**；艾雅法拉/望 通用型（法抗衰减 90%）。

**权重关系（务必据此组织结论）**：
- **DPS、泛用性、操作难度、回转时间是强度评测的关键点** —— 结论的主干应围绕这四项
- **生存是锦上添花的关键一环** —— 不是主干，但对承伤位与"以生存换输出"的分支（阵法术师/解放者）是硬指标
- ②③④ 与团队增益/控制同样**不并入 DPS 数字**，各自独立成栏或独立指标

### 操作难度口径（③，已实现）
**只给客观项 + 分级 + 理由，不合成假精确的单一分数**（主观权重由 agent 结合玩家水平给）。六类客观因素：
① 触发方式（受击回复=节奏由敌人定 > 攻击回复 > 自动开启/手动可控）
② 时机窗口（技能期 ≤10s 需卡点；永续几乎无压力）
③ 站位范围（范围扩大/缩小、对空、重量条件、单方向射程）
④ 部署准备（常态不攻击需预留准备时间、费用≥30、阻挡 0）
⑤ 前置条件（蓄力等待、弹药打完、击杀叠层、常态蓄力）
⑥ 回转负担（复用回转栏口径）
分级：低（<4）/ 中（4–7）/ 高（≥8），**分数仅作排序参考，结论看理由清单**。
实测：史尔特尔 低（永续）；能天使 低（窗口 15s）；玛恩纳 中（常态不攻击+阻挡0）；卡涅利安 中（常态不攻击+蓄力）。

### 回转时间口径（④，已实现）
`tools/rotation.mjs` —— 全部由 `spData` 推导、零假设：**首轮可用时间**（体感差异最大）、完整周期、空窗、覆盖率、
60s/90s 内可开次数；另处理永续、弹药型（持续随命中浮动）、可充能。受击回复按假设受击频率 0.5 次/秒折算。

**待补**：泛用性的体系化评分（跨场景覆盖 + 对高难场景的适应性）、操作难度模型（触发方式/时机/站位/部署约束）、回转时间单列（充能秒数 + 首轮可用时间）。

## 1. 输出栏（已实现，供对照）

- 主指标：分场景平均 DPS（6 标准场景 × 覆盖率加权）、技能期峰值、费用效率
- 成像机制：物理看 DEF / 法术看 RES；穿透（`penetrate`）与对敌减益（`enemyDebuff`）已计入
- 特殊形态：稳态 / 单次窗口爆发（burst）/ 陷阱触发（trap）/ 强化攻击（nextAttack）/ 元素损伤（element）
- 置信度标注：机制补丁涉及的干员须标注"数值含解析补丁"

## 2. 团队增益栏（标准设计）

### 2.1 数据来源

| 增益类型 | 数据 key / 描述特征 | 备注 |
|---|---|---|
| 减防 | `def` 负值 + 描述"使其/敌军…防御力-" | 对敌，队友物理输出受益 |
| 减抗 | `magic_resistance` 负值 + 描述指向敌人 | 对敌，队友法术输出受益 |
| 易伤/脆弱 | `fake_damage_scale`、`fake.b`、`damage_scale` | 受到伤害提升（乘法） |
| 虚弱 | `weak`、`weak[limit]` | 降敌攻击力（偏生存） |
| 队友攻击/攻速 buff | 描述含"友方/队友…攻击力+/攻击速度+" | 直接增伤 |
| 回费/续航 | 描述含"回复技力/费用" | 节奏价值（难量化，定性） |
| 治疗/护盾 | `heal_scale`、描述含"治疗/护盾" | 归生存维度，此处仅标注 |

### 2.2 维度与量化口径

| 维度 | 量化方式 |
|---|---|
| 幅度 | 减防/减抗：折算为"对标准场景我方输出的相对提升 %"（见 2.3）；易伤：直接取受到伤害提升 % |
| 覆盖率 | 增益持续时长 / 技能周期（与输出栏同一套覆盖率模型） |
| 范围/目标 | 单体 / 小范围 / 大范围 / 全场（从描述与 rangeId 判断） |
| 生效条件 | 常驻（天赋）/ 技能期 / 命中后（时序标注） |
| 叠加性 | 是否可叠加、是否与其他同类取最高 |
| 场景依赖 | 高甲/高抗/Boss 场景价值差异（LLM 判断） |

### 2.3 折算公式（相对提升）

```
物理减防：提升 = (ATK_基准 − DEF×(1−减防%)) / (ATK_基准 − DEF) − 1
法术减抗：提升 = (1 − (RES − 减抗)/100) / (1 − RES/100) − 1
易伤    ：提升 = 易伤值（如 +35% → ×1.35）
```
- `ATK_基准`/`DEF`/`RES` 取标准场景画像（如 400 防 / 50 抗），并注明基准假设
- 输出栏的"自身受益"与团队栏的"队友受益"用同一折算，但分别列示

### 2.4 评级框架（初定，待用户确认）

| 等级 | 团队增益量级（对标准场景队友输出的相对提升 × 覆盖率） |
|---|---|
| T0 | ≥40% 且覆盖率高 / 全场范围 |
| T1 | 20–40% |
| T2 | 10–20% |
| T3 | <10% 或条件苛刻 |

### 2.5 LLM 介入点（必须语义判断，不可硬规则）

- 增益的**实际可用性**：范围能否覆盖队友输出位、是否要求特定站位
- 与特定干员的**配合价值**（如减抗 + 法术大 C、脆弱 + 爆发窗口）
- **场景价值**：高难合约/Boss 攻坚中团队增益的权重远高于日常清杂
- 描述中的**隐含限制**（"攻击范围内""对空""仅地面""每 X 秒一次"）

## 3. 控制栏（标准设计）

### 3.1 数据来源与控制类型

| 控制类型 | key | 强度定位（玩家共识） |
|---|---|---|
| 眩晕 | `stun`、`attack@stun` | 硬控（最高档，可打断） |
| 冻结 | `frozen` | 硬控（最高档） |
| 睡眠 | `sleep` | 硬控（高，但被攻击唤醒） |
| 束缚 | `unmove`、`constraint`、`bind` | 中硬控（不能移动，仍可攻击） |
| 停顿/减速 | `sluggish`、`move_speed` 负值 | 软控（拖时间/聚怪） |
| 恐惧 | `fear` | 中（迫使移动） |

### 3.2 维度与量化口径

| 维度 | 量化方式 |
|---|---|
| 单次控制时长 | 每次触发附带的控制秒数 |
| **触发方式** | 攻击触发（每次攻击附带）/ 技能期持续 / 单次触发 / 天赋常驻 |
| **控制覆盖率** | 攻击触发：`单次时长 ÷ 技能期攻击间隔`（含攻速与 base_attack_time 修正）；持续型：技能覆盖率 |
| 范围与目标数 | 单体 / 范围 / 全场；群体晕眩 vs 单体晕眩 |
| 对 Boss 有效性 | 多数硬控对重量级/Boss 有抗性（LLM 判断 + 标注） |
| 对空 | 是否可作用于飞行单位 |

**关键教训（用户指正）**：控制强度 **≠ 单次时长**，必须按触发间隔折算覆盖率。
- 水月 S3：1s 晕眩，但攻击间隔 3.5s → 覆盖率仅 **28.6%**（控制不强）
- 水月 S2：1.3s 束缚，间隔缩短至 2.0s → 覆盖率 **65%**（控制远强于 S3）
- **保持"类型分级 + 时长分开列"，不做类型间数值换算**（眩晕 ≠ 减速，无法等价）

**模组纳入**：
- 模组会改变控制/输出强度（如**水月特限模组 ISW-α**：集成战略中目标数+1 并大力拖拽到面前、技能期间目标数再+2 → 拖拽=位移聚怪，间接强化控制覆盖）
- 数据仓库只有模组**元数据**（名称/类型/描述，`m.modules`）；**数值效果须 PRTS 解析** → 沉淀 `MODULE_OVERRIDES`（`tools/overrides.mjs`）
- 特限模组（ISW-*）**仅在对应玩法生效**，默认评测不启用，报告标注其存在与效果范围

### 3.3 评级框架（初定，待用户确认）

| 等级 | 控制量级 |
|---|---|
| T0 | 硬控 + 高覆盖率/大范围（铃兰级减速、群体眩晕链） |
| T1 | 硬控但覆盖率中等，或软控但覆盖面积极大 |
| T2 | 短时硬控 / 稳定软控 |
| T3 | 附带控制，非主要价值 |

### 3.4 LLM 介入点

- **控制类型价值换算**：眩晕 1 秒 ≠ 减速 1 秒（无法纯数值等价，需按场景定性加权）
- **与输出的协同**：控制带来的"我方输出窗口"（如把敌人定在输出位）
- **敌人抗性**：Boss/精英对控制的抗性差异（不同控制类型抗性不同）
- **反制与免疫**：描述里的免疫/抵抗条件

## 4. 生存栏（标准设计，2026 新增）

### 4.0 权重定位（用户明确，2026）

> **生存对强度推断通常是低权重维度** —— 大多数情况下其他干员（盾位/医疗）能保住高输出干员，
> 所以"自己能扛多少"往往**不是强度瓶颈**。评价一个输出干员时，输出与团队增益远比生存重要。

**生存成为核心维度的场景**（这几类必须单独给足权重）：

| 场景 | 原因 |
|---|---|
| **承伤位**（重装 / 站场近卫） | 它们的职责就是扛，生存即职能 |
| **"以生存换输出"的分支** | **阵法术师**（常态防御×3、法抗+20，技能开启后加成消失换群体法术输出）、**解放者**（常态不攻击、阻挡 0，攻击力蓄力到 +200% 在技能期兑现）—— 它们的生存与输出是同一枚硬币的两面 |
| **无法被友方治疗的干员** | 如泥岩"无法被友方角色治疗" → 医疗支援无效，生存只能靠自己 |
| **单守 / 低配 / 无治疗阵容** | 没有队友覆盖时，承伤能力直接决定能否开局 |

因此报告的 ④ 生存栏**不是每个干员的"评分项"**，而是：给承伤位与特化分支提供硬指标，
给输出位提供"会不会被秒"的风险提示。结论要按干员职能决定这两栏的权重。

### 4.1 数据来源

| 来源 | 内容 |
|---|---|
| 面板（`panel`） | maxHp / def / magicResistance / blockCnt / tauntLevel / 各类 `*Immune` |
| 天赋层（`talents`） | 自回（`hp_recovery_per_sec*`）、闪避（`prob` + 描述判定）、减伤（`damage_resistance`）、屏障（`max_hp_ratio`）、抵抗（`one_minus_status_resistance`）、保命（`min_hp_ratio`） |
| 模组层（`_moduleTrait`） | 模组特性带来的闪避/减速/防御（与 ②③ 同源，自动并入） |
| 技能层（技能 blackboard） | 技能期防御/法抗/生命加成、自回、减伤 → **常态与技能期分开报** |
| 来袭画像（`data/threat-scenarios.json`） | 从 1949 名敌人的 `atk / baseAttackTime` 统计出的 5 档标准压力 |

### 4.2 维度与量化口径

| 维度 | 口径 |
|---|---|
| 面板硬度 | 生命 / 防御 / 法抗 / 阻挡（含天赋%与模组属性） |
| 硬扛能力 | 对每档来袭画像：**每击伤害 → 可挨 N 击 → 撑 T 秒**（离散受击模型，见下） |
| 等效生命 EHP | `血池 × (来袭ATK/每击伤害) × 闪避倍率`（防御折算 × 闪避，各乘一次） |
| 闪避 | 物理/法术分别计，期望倍率 `1/(1−闪避率)`，上限 95% |
| 自回 | `每秒回血 = 最大生命×比例 + 固定值`；与承伤相抵得**净承伤** |
| 减伤 | 固定点数（先减）与百分比（后乘），均作用于每击 |
| 屏障 | 额外血池（如休谟斯 104% 上限 → +4% 生命） |
| 抵抗 | 异常状态时长减半（与 ③ 控制栏互为反制） |
| 团队生存 | 治疗输出估算（医疗：`攻击力/间隔`；`attack@heal_scale` 每秒型：`攻击力×系数`）、嘲讽转移仇恨 |

**离散受击模型（关键）**：不能用 `血池 ÷ 每秒承伤` 的连续模型 ——
1758 生命面对 1394/击、间隔 1.3s，连续模型给 1.64s，实际是**第 2 击（t=2.6s）倒下**；
单击超过总生命时（如 2520/击）连续模型会误报 4.9s，实际**1 击即倒**。
实现：`engine/survival.mjs: surviveSim()` —— 逐次扣血、击间回血、上限 180s。

### 4.3 评级框架（初定，待用户确认）

| 等级 | 生存量级 |
|---|---|
| T0 | 对物理·精英（384.6DPS）站得住，或对物理·狂暴可撑 10s+ |
| T1 | 对物理·精英可撑 20s+，或高闪避/高自回显著改写承伤 |
| T2 | 对物理·精英可撑 8–20s |
| T3 | 承伤接近裸身（每击即掉大半血），依赖治疗支援 |

### 4.4 LLM 介入点

- **阵型与阻挡分流**：谁在承伤、被几个敌人打（本栏按**单敌人**给数，集火按线性放大需你判断）
- **治疗支援**：有无医疗/守护者覆盖，实际生存被大幅改写
- **条件型特性的可用性**：如星熊「阻挡敌人时防御力+20%」—— 阻挡是常态还是偶发？
- **闪避的方差风险**：65% 闪避按期望折算，但连续两次不闪即可能暴毙（高难保命需按最坏情况）
- **免疫/抵抗的实际价值**：取决于关卡敌人的控制与元素损伤配置

## 5. 报告形态（四栏并列）

```
【干员名】稀有度 · 职业/分支
├─ ① 输出栏：分场景 DPS 画像 / 技能形态 / 穿透与自身减益标注
├─ ② 团队增益栏：增益类型 + 幅度 + 覆盖率 + 标准场景折算提升 + 范围/条件（含 LLM 评注）
├─ ③ 控制栏：控制类型 + 时长 + 覆盖率 + 范围/对空/Boss 有效性（含 LLM 评注）
```
