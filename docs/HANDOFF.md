## 1. 项目定位（务必先读，避免方向跑偏）

**明日方舟干员强度评测 Agent** —— 在 DeepSeek Harness 中，用本地游戏数据 + 数值引擎评判干员强度。

**用户明确定位（重要）**：
- 目标是**强度量级评判 + 场景适配对比**，**不追求理论极限复现**（极限轴属玩法层，不混进默认结论）
- 输出**三栏并列**：① 输出栏 / ② 团队增益栏 / ③ 控制栏（②③ 不并入 DPS 数字）
- 控制栏**保持"类型分级 + 时长分开列"，不做类型间数值换算**
- 核心诉求：**能读懂技能描述与天赋**，而不是"为个别干员打补丁应付测试"

**用户工作方式**：会提供实测/机制细节校准数值（如望的十字 5 枚、水月的控制覆盖率），要求解析能力**通用化**而非个例修补。

## 4. 核心架构（改代码前必须理解）

### 4.1 解析双层
- **第一层 `patterns.mjs`**：描述表述 → 引擎参数（数据驱动，覆盖高频）；**新增通用模式必须写这里**
- **第二层 `overrides.mjs`**：LLM 读描述产出补丁（长尾独有机制）；判断标准 = 同一表述出现于多个干员 → 属第一层

### 4.2 技能形态分类（决定用哪个通道，套错量级全错）
稳态持续（覆盖率模型）／单次窗口爆发（burst）／陷阱触发（trap）／下次攻击强化（nextAttack）／元素累积（element）／技能期停止攻击（noAttack）

### 4.3 四栏（`docs/eval-standards.md`）
- ① 输出栏：自己打多少（DPS 画像/分场景/费效）
- ② 团队增益栏：让队友多打多少（折算基准 400防/50抗/基准ATK800）
- ③ 控制栏：控制时长 ÷ 触发间隔 = 覆盖率；类型分级（硬控/中硬控/软控）；**不做类型换算**
- ④ 生存栏：分档硬扛（每击/可挨击数/秒数）+ 自回/闪避/减伤/屏障/抵抗/免疫 + 团队生存；**离散受击模型**

### 4.4 口径分层
单次部署伤害 / 单次技能总伤 / 轴总伤 / 轴 DPS —— **分开报，不混算**；轴长属玩法层参数

### 4.5 模组层（`tools/modules.mjs`，2026 新增）
**核心设计**：模组不是"另一套提取逻辑"，而是**构造一个"模组修改后的干员对象"**再交给既有提取器 ——
天赋/减益/穿透/特性/控制/团队增益的全部解析逻辑直接复用，避免语义分叉。

- 属性加成直接叠加到 `panel`（模组攻速走 `talent.aspd` 通道）
- 天赋更新是**替换**语义（`talentIndex` 命中则覆盖）；`isHideTalent` 例外按**新增**处理
- 特性黑匣子为空的场合（减速等）用**描述解析兜底**（正则抽 `移动速度-20%`）
- 模组攻速/控制特性经 `op._moduleAspd` / `op._moduleTrait` 传给 ③ 控制栏
- 穿透三类：无条件计入 / 叠层按叠满计入并标注 / **条件型不计入仅标注**

### 4.6 生存层（`engine/survival.mjs` + `tools/survival.mjs`，2026 新增）
- **来袭画像**：`data/threat-scenarios.json` 5 档（物理清杂/精英/狂暴 + 法术中压/高压），ATK/间隔取自
  `enemy_database.json` 1949 名敌人的真实分布，锚点是可确定判定伤害类型的真实敌人
- **离散受击模型**（核心）：逐次扣血 + 击间回血，**不要改回 `血池 ÷ 每秒承伤`**（会误报，见 §5）
- **等效生命** = 血池 × 防御折算倍率 × 闪避倍率（**各乘一次**；闪避乘两次是曾经的 bug）
- 常态与技能期**分开报**；`prob` 是通用概率键，必须靠描述区分闪避，且"物理和法术闪避"要双算
- 模组特性带来的闪避/自回自动并入（走"模组修改后的干员对象"同一机制）
- 独立入口 `tools/survival-eval.mjs`（**不依赖技能** —— 21 名无技能干员只能这样评生存）

---

### 4.7 召唤物层（`tools/summon.mjs` + `engine/summonDps`，2026 新增）
- **独立输出线**：不并入 `skillDps`/`avgDps`，报告单列并写"不相加"
- **分类三判据**（缺一会把最大的漏掉或把治疗无人机算成输出）：倍率键 >1 / atk>100 / 人工核对例外；再排除治疗型
- **通道互斥**：陷阱师产出归 `trap`，`summon` 硬排除（`TRAP_CHANNEL_IDS`）—— 否则双算
- **同时存在数默认 1**：`cnt`/「可以使用5个」是总数；令/麦哲伦/电弧的召唤物是"技能功能模式"，
  同一时刻只有 1 种 → **不能乘 3**。只有直接点名该召唤物的「最多存在N个」才采信
- **未建模**：召唤物自身技能里**一次性入场/触发伤害**（18 条）、周期伤害、概率型 → 报告标注为下限；
  已建模的只有"无条件改变普攻"的 3 条（见 §18）

### 4.8 召唤物自身技能层（`data/summons.json` 的 `ownSkill`，2026 新增）
- **不能用召唤物技能序号反推干员技能序号**（令三形态共用 `sktok_ling_soul3`）→ 只能按效果判定
- **`2.` 前缀是"第二形态"**（弦惊高级形态），**不作用于基础形态**，硬套会算成 −20% 的错值 → 跳过
- 只建模两类：攻击力倍率（`atk` 加成 / `atk_scale` 提升至）、攻击间隔（`attack_speed` **是百分比** / `base_attack_time` 秒差）
- **叠层消耗型必须最先判**（傀影「血色乐章」含"部署后立即"，若先跑关键词排除会被误杀 —— **踩过**）
- 一次性触发伤害另有 burst 层（§19）：**只报每次触发、不给 DPS**

### 4.9 条件型加成与索敌层（`tools/conditional.mjs`，2026 新增）
- **对空加成**（`atk_scale_to_fly`）：只对空生效 → **不进地面场景 DPS**；全库仅阿罗玛
- **索敌规则**（`优先攻击X`，57 名）：进模式库；**来源必须含 `op.trait.description`**（否则漏 23 名狙击）
- **蓄力两态**（9 名）：两态并列展示，**不自动改基准 DPS**
- 验证 `tools/verify-conditional.mjs`：三条都断言"不污染锚点"（银灰 5524.6 不变）
- **三条"不猜"原则**：场景不成立就不计（对空）/ 只改落点就不进数值（索敌）/ 没有公共编码就不硬接（蓄力）

## 5. 踩坑记录（最容易重复犯错，务必看）

| 坑 | 教训 |
|---|---|
| 把天下劫当稳态 DPS | **技能形态必须先分类**；单次爆发不是持续输出 |
| 从实测总伤反推"8引爆×10段" | 反推 ≠ 推导；10 段纯属巧合（正解：每次部署十字 5 枚） |
| 漏掉天赋 1 与技能"额外部署"的叠加 | **空间与叠加推理**：一次操作生成几个单位？范围形状？ |
| 只按单次时长评控制 | **控制强度 = 时长 ÷ 触发间隔**（水月 S3 仅 28.6%） |
| 减益单位混用 | 天赋用小数（-0.44=44点），技能用点数（-20=20点）→ 需归一 |
| 额外目标数双算 | bb `attack@max_target` 与描述"额外攻击N个"是同一信息 → 描述优先，按 1+N |
| 陷阱师 atk_scale 误当普攻倍率 | 陷阱师的 atk_scale 是陷阱伤害 → 归 trap 通道，普攻 ×1 |
| 钼铅漏判 | 陷阱触发表述用"引爆"不止"触发" |
| 模组数值以为在 PRTS | **仓库里就有**：`battle_equip_table.json`（505 个 ADVANCED 模组全含数值）|
| 模组属性加成当成增量累加 | `attributeBlackboard` 是**该级累积总值**，取 L3 即满配 |
| 模组天赋当成叠加 | 是**替换**语义（加法会双算，如能天使 atk 0.08 会变 0.16）|
| `isHideTalent` 的隐藏天赋当替换 | 会**误删本体天赋**（深蓝之籽的 hp_ratio 顶掉「创伤性癔症」）|
| 同槽位多条候选只取一条 | 需**合并**（描述覆盖包 `#` + 数值包 `1`，特限模组就是这样）|
| 天赋穿透一律计入 | 多数是**条件型**（沉睡/重量/概率/击倒）→ 直接计入会高估，须分流 |
| 天赋负数 atk 当自身减攻 | 描述指向敌人 = **对敌减攻**（山/泡泡/焰影苇草）；只有"自身"才是自身惩罚（瑰盐）|
| 信任旧锚点做回归 | 银灰 4735 / 多萝西 169.5 等**记录于"天赋计入面板"之前**，缺天赋加成 → 用 `tools/anchors.mjs` 重建 |
| 生存时长用"血池÷每秒承伤" | 连续模型忽略伤害离散性：1758 血 vs 2520/击会误报 4.9s，**实际 1 击即倒** → 必须离散模拟 |
| 等效生命把闪避乘两次 | `EHP = 血池 × 防御折算 × 闪避倍率`，三项**各乘一次**（写在 `engine/survival.mjs`）|
| `prob` 当闪避直接用 | `prob` 是通用概率键（还用于天赋触发/额外治疗）→ 必须靠描述含"闪避"判定 |
| "物理和法术闪避"只算一种 | 深蓝之籽 65% 是**物法双闪** → 描述含"物理和法术闪避"要双算 |
| 模组顺序直接用数组序 | 数组顺序 ≠ `charEquipOrder`（星熊/山的 X·Y 是反的）→ 必须排序，否则"默认模组"选错、与 PRTS 编号错位 |
| 模组特性自身加成单方计入 | 基础分支特性缺失时不能单方计入；**现已补齐基础特性** → 改为按"追加/覆盖"算净增量 |
| **特性文本以为在 `trait` 字段** | 干员级 `trait` 只在**特性带数值**时非空；**文本一律在干员级 `description`** —— 只读 `trait` 会让 454 人特性全空（曾导致水月本体 50% 闪避被漏算）|
| **模组特性一律当"更新"** | 必须看 `additionalDescription`（**追加**，基础特性仍在）vs `overrideDescripton`（**覆盖**）；搞混会把水月 Y 的 65% 叠加到基础 50% 上变成 115% |
| 条件型特性硬套面板 | 解放者"技能未开启时攻击力+200%"、阵法术师"通常时防御+200%"按技能开/关两态生效 → **这两个分支已由 `tools/branch-traits.mjs` 正式建两态**，其余仍只标注 |
| **特性里 `def: 2` 当成 +2 点** | 正向 `def`/`max_hp`/`atk` 在特性里**恒为小数比例**（2 = +200%）→ 按键值大小判断会把阵法师的防御×3 算成 +2 |
| **`atk_scale` 优先于 `attack@atk_scale`** | 两者并存时（全库 4 个技能）应优先 `attack@atk_scale`；否则**玛恩纳 S3 被算成 0.12 倍**（技能期 DPS 41.7，就是这个异常暴露了 bug）|
| **天赋 `atk>1` 当百分比** | 天赋里 `atk/def/max_hp > 1` 多为**固定点数**（乌尔比安"攻击力提高30"、嘉维尔"防御力+120"）→ 早期算成"攻击+3000%"（ATK ×31、DPS 29023）。须按 **描述里是否出现对应百分数** 判定（红豆 1.1→"+110%"✓其实例）|
| 天赋指向"友方"的加成并入自身 | 闪灵"攻击范围内的友方单位防御力+65" → 收益对象是队友，应只进 ② 团队增益栏（`forAllies` 守卫）|
| 爆发通道默认不吃 DEF/RES | `burstDeployDamage` 原为 `atk×段数×倍率` → 爆发干员跨场景恒定。已加 **可选** `mitigation:{def,res}`（**默认关闭以保锚点**：望 179056 不变），基准表/泛用性传入实际 DEF/RES |
| **pnpm/npm 安装依赖失败（ECONNREFUSED）** | 根因是 ~/.npmrc 写死 proxy=http://127.0.0.1:7897 而该代理常不在线（node fetch 直连正常）。解法：临时把 ~/.npmrc 换成只含 registry 的内容 → pnpm install → 立刻还原；或用 app/web/.npmrc.local |
| 用 PowerShell 改含中文的源码 | `Set-Content` 与内联 `node -e` 的引号转义都会破坏内容 → 一律用 write/edit 工具 |
| **召唤物的 `cnt` 当同时存在数** | `cnt`/「可以使用5个」是**总数/携带上限**。令/麦哲伦/电弧写作「最多同时部署3个」，而它们的召唤物是**技能功能模式**（同一时刻只 1 种）→ 乘 3 会高估 3 倍 |
| **陷阱师产出进 `summon` 通道** | 罗宾「夹子」/霜华「迎宾踏垫」/多萝西「共振装置」/钼铅/望 已归 `trap` 通道 → 再进 summon 就是**双算**（与"陷阱师 atk_scale 误当普攻倍率"同类） |
| **只按 `atk_scale` 筛伤害型召唤物** | 倍率键是"有则一定是伤害"，但**没有不代表不是** —— Mon3tr/令/乌尔比安/维什戴尔都是纯普攻，会被漏掉 |
| **占位装置判据写成 `atk=100 && interval=1`** | 会误杀真召唤物（沙之碑 5000 血/阻挡3、铁钳号 6000 血）→ 占位是 **`atk=100 且 间隔=1 且 生命=100`** |
| **治疗型召唤物当输出** | 赫默医疗探机 atk125/0.5 是**治疗量**；巫恋诅咒娃娃是减攻减防图腾 → `kind: support` 单列，不计 DPS |
| **用文本「持续N秒」当召唤物寿命** | 那是减益/护盾时长（夜烟 抗性-23% 持续1秒、罗比菈塔 护盾 25s）→ 只认黑匣子 `attack@tokenduration`，或语义层带原文引用的条目 |
| **`attack@tokenduration` 读错层级** | 它在**干员天赋 `talents[].candidates[].blackboard`**，不在召唤物自身技能里（召唤物技能只有 `skcom_withdraw`）|
| **采信 LLM 给的 token id** | 子代理**编造了 4 个 id**（打字机真实 `token_10026_bgsnow_subbow`，它写 `10014`）→ 关联一律按 `owner+name`/代号段**确定性**解析 |
| **采信 LLM 的 `existence` 判定** | 它把麦哲伦无人机判成 `skillOnly` 却引用了**电弧的句子**；无人机实际"携带即有、不绑技能" → 引用与结论不对应的判定一律不采信 |
| **把召唤物技能的 `atk_scale` 当普攻倍率** | 那是**一次性入场/触发伤害**（梅尔「爆破回收」6×、傀影「夜幕突袭」3×、W 2.8×）→ 套上去会把持续 DPS 算成 6 倍。第一版判据"有倍率键即建模"一次命中 19 条，**其中 16 条是错的** |
| **叠层判定排在关键词排除之后** | 傀影「血色乐章」描述含"部署后立即"→ 被一次性入场规则误杀。叠层"每击消耗一层"是**最强的普攻强化证据**，必须最先判 |
| **召唤物 `attack_speed=60` 当成 60 秒** | `attack_speed` 是**百分比**（+60% → 间隔 ÷1.6）；`base_attack_time` 才是秒差 |
| **弦惊 `2.` 前缀键套到基础形态** | `2.` 是**第二形态**（高级形态）；`2.atk=0.8` 直接套会算成"攻击力 −20%"，而描述写的是"大幅度强化" → 必须跳过并标注未建模 |
| **只用召唤物技能序号推形态** | 令三形态共用 `sktok_ling_soul3` → 序号区分不了形态（形态由功能决定）|
| **模式库只跑技能描述** | 狙击系的「优先攻击空中单位」在**分支特性**里 → 只看技能描述会**漏掉 23 名狙击**。索敌/对空类模式必须把 `op.trait.description` 一并作为来源 |
| **文本里的 `\n` 当成真换行** | 描述里的换行是**转义序列**，`[^\n]` 拦不住 → 苦艾的索敌被抽成 `当前生命百分比最低的敌人\n持续时间无限`。要去掉 `\\` 并在"且/并且"处截断 |
| **蓄力数值当公共编码** | 9 名蓄力干员**没有任何统一编码**（有的翻倍、有的换值、有的延时长）→ 硬接引擎参数会算错。改为两态并列展示、不自动改基准 |
| **触发伤害给 DPS** | 触发次数取决于部署位/回收节奏（玩法层），描述推导不出 → 只报"每次触发"，与「天下劫」需用户给轴同理 |
| **对空加成并进地面场景** | `atk_scale_to_fly` 是"对**空中敌人**额外伤害"，而 6 场景+5 画像**全是地面** → 并进去等于给所有场景白送加成。只标注+给空战参考值 |

**网络事实**：`curl` 的 schannel 在沙箱内不可用；**用 `node fetch` 抓 HTTPS 可以**（PRTS/GitHub 都通）。git 需带 `-c http.proxy= -c https.proxy= -c http.sslBackend=openssl`（本机 7897 代理常不在线）。
