# DPS 计算严谨来源（计算链路说明）

> 本文档回答"当前引擎的 DPS 是怎么算出来的、依据是什么、哪里不严谨"。
> 目的：让你（用户）在扩展模型（元素损伤/陷阱/召唤/辅助）前，完全清楚现有实现的每个环节。

## 0. 数据来源（全部来自 Kengxxiao/ArknightsGameData，zh_CN）

| 数据 | 路径 | 提取逻辑（tools/build-dataset.mjs） |
|---|---|---|
| 满练面板 | `excel/character_table.json` | `phases[最后一个].attributesKeyFrames[最后一个].data`（= E2 满级面板），取 `maxHp/atk/def/magicResistance/cost/blockCnt/baseAttackTime/respawnTime/spRecoveryPerSec` |
| 技能专三 | `excel/skill_table.json` | `skills[skillId].levels[9]`（levels 1-7=技能等级，8/9/10=专一/二/三），取 `name/description/duration/spData{spType,spCost,initSp,increment}/blackboard` |
| 敌人 | `levels/enemydata/enemy_database.json` | 场景库 DEF/RES 分层（见 data/scenarios.json） |

## 1. 伤害公式（engine/dps-engine.mjs）

```
物理： max(⌊ATK×倍率 − DEF⌋, ⌊ATK×倍率×0.05⌋)          ← 线性减防，5% 保底
法术： max(⌊ATK×倍率×(1−RES/100)⌋, ⌊ATK×倍率×0.05⌋)   ← 百分比减抗，5% 保底
真实： ⌊ATK×倍率⌋                                     ← 无视双防
单次合计伤害 = 单段伤害 × 段数(hits) × 目标数(targets)
```

- **依据**：明日方舟公开伤害机制（社区/PRTS 共识）。**未用游戏内实测校准**，`floor` 取整与 5% 保底是社区推导值，是首要待核实项。

## 2. 攻速与攻击间隔

```
攻击间隔 = 基础间隔 / (1 + 攻速加成/100)          # attackInterval()
技能期间隔 = (基础间隔 + 秒差) / (1 + 攻速%/100)    # skillInterval()
```

- `base_attack_time`（秒差，如火山 −1.1s）与 `attack_speed`（百分比，如棘刺 +25）两种编码分别映射到 `baseAttackTimeDelta` 与 `aspdBonus`。
- **待核实**：多来源攻速（技能+天赋+模组）叠加方式（加法/乘法）未建模（当前仅技能单一来源）。

## 3. SP 与技能覆盖率（skillCoverage）

```
充能时间 chargeTime = (spCost − spStart) / 回复速率
回复速率：
  auto   → 面板 spRecoveryPerSec（方舟统一 1/s，个别技能/天赋可改）
  attack → increment / 技能期攻击间隔（每次攻击回 increment SP）
  hit    → hitAssumptionPerSec × increment（受击频率为场景假设值，默认 0.5 次/秒，可配置）
覆盖率 = duration / (chargeTime + duration)
永续（duration<0）：覆盖率 = 1
```

- ✅ **已修复（SP 模型 v2）**：auto 回复速率已改用面板 `spRecoveryPerSec`（不再硬编码）；attack 型已计入 `increment`（每击回 SP 量）；受击回复（hit）已实现，但**依赖受击频率假设**（`hitAssumptionPerSec`，默认 0.5 次/秒 —— 场景相关，高难图被集火时实际值更高，评价受击回复型干员时需按场景调整此参数）。
- ⚠️ 仍未模拟：SP 溢出、技能期间是否回 SP、首轮充能细节。

## 4. 平均 DPS（avgDps）

```
平均DPS = 技能期DPS × 覆盖率 + 平A DPS × (1 − 覆盖率)
```

## 5. 强化攻击型（nextAttackDps，"下次攻击"技能）

```
n = ⌈spCost / increment⌉  次攻击为一轮
平均DPS = (强化伤害 ×1 + 平A伤害×(n−1)) / (n × 攻击间隔)
```

## 7. 已知不严谨清单（扩展模型前必读）

1. **伤害公式未实测校准**：floor 取整、5% 保底、保底是否适用真实伤害。
2. **SP 模型（v2 已修）**：auto 已用面板 `spRecoveryPerSec`、attack 已计入 increment、受击回复已实现（依赖 `hitAssumptionPerSec` 假设）；仍简化：SP 溢出、技能期回 SP、首轮充能。
3. **攻速叠加未建模**：多来源攻速（技能+天赋+模组）的叠加方式未知。
4. **多目标理想化**：假设所有目标同时吃到全部伤害，忽略弹道/索敌/射程内的实际命中数。
5. **覆盖率理想化**：周期模型忽略前摇/后摇、技能结束到下一轮充能的无缝衔接。
6. **面板未合并**：天赋/潜能/信赖/模组加成未计入（当前为裸 E2 满级面板）。
7. **语义映射长尾**：blackboard key 语义多样（fk 法伤、heal_scale 治疗、ep_damage 元素等），启发式覆盖不全 → override 表逐例补。
8. **缺失机制族**（无模型）：召唤物（令/凯尔希）、治疗/增益/控制类辅助、存储型技能。元素损伤已建累积+爆发模型（见 §10）；陷阱/棋子已建触发模型 v1（见 §11）。

## 11. 陷阱/棋子模型（v1，6 陷阱师：望/多萝西/艾拉/罗宾/霜华/钼铅）

**机制识别**（evaluate.mjs）：`subProfessionId === 'traper'` + 技能描述含"触发/引爆/被动效果" + blackboard 有 `atk_scale`/`attack@atk_scale`（陷阱伤害倍率）。陷阱师的普攻倍率强制 1（atk_scale 归陷阱通道，避免误用）。

**计算**：
```
陷阱触发 DPS = ATK × 陷阱倍率 × 每轮产出数(cnt) ÷ 技能再充能秒(cdSec)
cdSec = (spCost − initSp) / spRecoveryPerSec（自动回复产陷阱周期）
```

**已验证**：望 S3（8 枚 ×3.8 ÷12s ≈ 1492/s）、望 S2（2 枚 ×5.8 ÷15s ≈ 455/s）、罗宾/多萝西（1 枚 ×3.5 ÷12s）。

**⚠️ 假设与未建模**：
- 触发节奏假设 = 技能 CD（高压场景"产出即被触发"，理想上限）—— 真实触发率随敌人波次/走位大幅波动。
- 目标数假设 = 1（多萝西 S2/S3、望 S2 为范围/AOE 型，实际打多个 → 低估）。
- 波次爆发型（望 S3）按"cnt 枚全触发"摊平，非一次性爆发形态。
- 陷阱师本体普攻为独立通道（间隔 0.85s 快速普攻），报告分栏展示。
- 艾拉 S3 为"枪弹模式"本体爆发（无陷阱触发伤害），走普攻通道 ✓；艾拉 S1/S2 为陷阱增益/眩晕型（无直接伤害），未量化控制价值。

## 10. 元素损伤累积模型（v1）

**数据来源**：技能/天赋 blackboard 的 `ep_damage_ratio` / `attack@ep_damage_ratio`（每击附带 ATK×ratio 的元素损伤）；损伤类型（神经/侵蚀/灼燃/凋亡）从技能描述文本识别。

**计算**：
```
每击型：元素累积/秒 = ATK × ratio × 目标数 × 攻击频率（技能期攻速）
dot 型 ：元素累积/秒 = ATK × ratio × 目标数（"每秒受到 X% 损伤"，如酒神 S3）
```

**语义要点（勘察实证）**：
- 主流 = 本源术士"攻击附带损伤"（妮芙 S1 15%凋亡、塑心 S1 110%凋亡、凛视 S2 35%）
- dot 型特例：酒神 S3（每秒10%神经损伤）、烛煌 S1（每秒30%灼燃）
- 异类：余（受击/友方法术附带灼燃）、温米/烛煌天赋的爆发增伤（ep_damage_scale）

**⚠️ 未建模部分（已核实 + 仍简化）**：
- ✅ **损伤条阈值与爆发数值已从 PRTS「元素」页核实**（客户端 2.7.61）：MAX_EP 普通 1000 / 领袖 2000；敌人爆条收益 = 神经 6000+麻痹 / 侵蚀 5000+-120防 / 灼燃 7000+法抗-20 / 凋亡 800/s×15s+50%虚弱（表 `ELEMENT_BREAK_ON_ENEMY`）。
- 爆发收益模型假设：**爆发冷却 ≈ 爆发持续秒数**（PRTS 仅说"进入冷却、元素条缓慢恢复"，精确恢复速率未给出）；领袖只翻倍 MAX_EP，未计领袖的 EP 恢复/抵抗。
- 元素累积"速率"目前是**技能期速率**，未做覆盖率加权；对"单次攻击附带大量损伤"型技能（塑心 S1）按频率近似有偏差。
- 元素累积不区分普攻（本源术士天赋自带）与技能附带 —— 天赋层元素损伤（妮芙天赋 0.4 等）未并入。

**实际评测输出（v2）**：
```
元素损伤：凋亡损伤累积 61.4/秒（技能期）· 爆发收益约 383.6/秒（普通敌人）/ 252.3/秒（领袖，条2000）
```
爆发的减益/控制（法抗-20、减防、麻痹、虚弱）只计入 note，未折算为数值收益。

## 12. LLM 描述解析层（架构：读描述 → 机制补丁 → 引擎）

**问题**：规则引擎（blackboard 通用映射）只能覆盖主流模式；天赋与描述中的特殊机制（联动增伤/无视抗性/特殊触发）语义无限，规则追不上。

**方案**（评测 agent 流程，skill 固化）：
1. `node tools/dump-op.mjs 干员` → 输出天赋+技能描述原文与 blackboard（LLM 输入源）
2. agent 读描述 → 提取规则无法推导的机制 → 生成**机制补丁**（结构化 JSON）
3. 沉淀 `tools/overrides.mjs`（人工审核区）
4. 引擎消费补丁重算 → 报告说明补丁与依据

**已沉淀**：望 S3 `trapPatch: { multBonusPct: 0.36, resPenetrate: 30 }`（棋子联动 +12%×3 层 + 无视 10 抗×3 层）→ 触发 DPS 1492→2029。棘刺 S3 attackMult（远程惩罚机制）。

**待办**：天赋通用规则计入（atk 加法加成等纯规则部分）；自动调 LLM 生成补丁的脚本化（当前为 agent 手动解析）。

## 13. 模组层（数值来源：battle_equip_table.json，2026 补）

**数据来源更正**：模组数值**不在 PRTS，就在游戏数据仓库里** ——
`ArknightsGameData/zh_CN/gamedata/excel/battle_equip_table.json`（5.6 MB）含全部 ADVANCED 模组的
属性加成 / 天赋更新 / 特性更新（`uniequip_table.json` 是元数据）。构建：`node tools/build-modules.mjs` → `data/modules.json`。

**覆盖**：898 个模组中 505 个有战斗数据；**393 个 ORIGINAL（干员证章）一个都没有** → 证章在数据层无战斗数值，启用它对计算无影响（评测时会明确提示）。

> **双侧验证**：PRTS 干员页对 ADVANCED 模组有 `模组N数据=max_hp:330;atk:70` 字段，而 `初始模组名`（证章）**没有"数据"字段** —— 与 `battle_equip_table.json` 的缺失完全一致，两个独立来源互相印证：证章确实不提供属性加成。
>
> **大规模交叉校验**（`node tools/crosscheck-prts-modules.mjs` → `docs/module-prts-crosscheck.md`）：
> 抽样 62 名干员（含全部特限干员 + 各稀有度分层）、**逐模组按名称配对比对 105 个模组的属性数值 → 105 一致 / 0 不一致 / 0 未取到**；
> 证章抽样 62 名，带属性数据的 0 例。校验同时印证了两条口径：
> ① PRTS 的 `模组N数据` 是**满级(L3)总值**（水月 AMB-X = `max_hp:220;atk:90` = 我们的 L3 值），与"累积总值"读法一致；
> ② PRTS 的 `模组N` 序列**包含特限模组**，所以必须**按名称配对**而非按序号 —— 早期一版报告按序号配对，把能天使 X/Y 比串，产生了 2 条假"不一致"。

### 语义（踩坑必读）
| 项 | 规则 |
|---|---|
| `phases[].attributeBlackboard` | 是**该等级的累积总值**（水月 002：atk 60→75→90），取 L3 即满配，**勿累加** |
| 天赋更新 | **替换**语义：`talentIndex` 在基础天赋范围内 → 覆盖该天赋 |
| `talentIndex` 超出基础天赋数 / 为 -1 | 模组**新增**天赋 |
| `isHideTalent: true` | 即便带 talentIndex 也按**新增隐藏效果**处理（否则会误删本体天赋，如深蓝之籽顶掉「创伤性癔症」） |
| 同槽位多条候选 | 需**合并**（描述覆盖包 + 数值包，如特限模组的 `#` 与 `1`），按 `requiredPotentialRank` 升序覆盖 |
| 潜能候选 | 取 `requiredPotentialRank` 最高者 —— 与数据集天赋取满潜值的既有约定一致 |
| `validInGameTag: 'roguelike'` | 增益**仅集成战略生效**（21 个特限模组），常规关卡按 0 增益理解 |

### 实现方式（关键设计）
**构造"模组修改后的干员对象"**（`tools/modules.mjs`: `applyModule`）再交给既有提取器，而不是让每个提取器各自理解模组 ——
天赋/减益/穿透/特性/控制/团队增益的全部既有解析逻辑直接复用，避免语义分叉。
模组攻速（属性和天赋两条来源）与控制特性通过 `op._moduleAspd` / `op._moduleTrait` 传给 ③ 控制栏。

### 天赋穿透（通用能力，本次新增）
天赋层的 `def_penetrate_fixed` / `def_penetrate` / `magic_resist_penetrate_fixed` 此前**完全被忽略**，
现按三类处理（18 名干员受影响）：
- **无条件型**（"攻击无视目标175防御"）→ 计入 DPS
- **叠层型**（"连续攻击时逐渐无视…最高50%"）→ 按**叠满值**计入并标注
- **条件型**（"对沉睡敌人"/"击倒敌人后"/"重量≥3"/"50%概率"）→ **不计入**，仅在报告标注条件（配沉睡队时早露/埃拉托的穿透才生效）

### 已知不严谨
- 模组的**条件型特性**（对空/距离/闪避/阻挡）不自动折算 —— 报告给出原文与 ⚠ 提示，由 agent 按场景判断
- 模组特性的减速已按**常驻光环**处理（覆盖率视为 100%，无时长概念）
- 模组的 `sp_recovery_per_sec` 等含 0 值的隐藏键会显示在效果文本里（噪声，不影响计算）

## 14. 生存模型（④ 生存栏，2026 新增）

**与输出侧同构**：承受伤害用同一套公式，只是"我方 ATK"换成"敌方 ATK"、"敌方 DEF"换成"我方 DEF"。
```
每击伤害 = max(⌊来袭ATK − 我方DEF⌋, ⌊来袭ATK × 5%⌋)              # 物理
         = max(⌊来袭ATK × (1 − 我方RES/100)⌋, ⌊来袭ATK × 5%⌋)      # 法术
减伤顺序：固定点数先减、百分比后乘，最后套 5% 下限（与输出侧 减益→穿透 顺序对称）
```
实现：`engine/survival.mjs`（纯数学）/ `tools/survival.mjs`（提取与呈现）。

### 来袭画像（`data/threat-scenarios.json`）
从 `enemy_database.json` 的 **1949 名敌人**统计 `atk / baseAttackTime`（已排除 atk>5000 或 间隔<0.5s 的地图装置/演出类）：

| 画像 | ATK/间隔 | DPS | 锚点敌人 |
|---|---|---|---|
| 物理·清杂 | 550 / 3.0s | 183.3 | 富营养的猎食者（= p50） |
| 物理·精英 | 1000 / 2.6s | 384.6 | 重装五十夫长 |
| 物理·狂暴 | 1750 / 1.3s | 1346.2 | 狂暴宿主组长（≈p97） |
| 法术·中压 | 800 / 2.5s | 320 | 爆裂冰法师 |
| 法术·高压 | 3600 / 7.0s | 514.3 | 巫术巨像 |

> **⚠ 敌人伤害类型不在数据层**：法术攻击由 prefab 决定，`enemy_database` 无字段（用名字里的"术/法"过滤会被"**战术**队"这类词误命中）。因此画像的 ATK/间隔取自真实分布，**伤害类型由"名字可确定判定"的锚点敌人设定**。

### 离散受击模型（关键，勿改回连续模型）
生存时长**不能**用 `血池 ÷ 每秒承伤`：
- 1758 生命 vs 1394/击、间隔 1.3s → 连续模型 1.64s，**实际第 2 击（t=2.6s）倒下**
- 1758 生命 vs 2520/击（法术·高压）→ 连续模型 4.9s，**实际 1 击即倒**

所以用 `surviveSim()`：逐次扣血（首击在 t=间隔）、击间按 HPS 回血、上限 180s。自回 ≥ 承伤时判为"站得住"。
等效生命 `EHP = 血池 × (来袭ATK/每击伤害) × 闪避倍率`（**三项各乘一次** —— 早期版本把闪避乘了两次，是 bug）。

### 覆盖的生存机制（通用解析，非个例补丁）
| 机制 | 数据键 | 判定要点 |
|---|---|---|
| 自回 | `hp_recovery_per_sec_by_max_hp_ratio` / `hp_recovery_per_sec` | 比例型×最大生命 + 固定型 |
| 闪避 | `prob` | `prob` 是通用概率键，**必须靠描述区分**；"物理和法术闪避"要**双算**（早期只算法术） |
| 减伤 | `damage_resistance` | \|v\|≤1 = 百分比，>1 = 固定点数 |
| 屏障 | `max_hp_ratio` + 描述含"屏障" | 上限超出 100% 的部分即屏障 |
| 抵抗 | `one_minus_status_resistance` | 异常状态时长减半（与 ③ 控制栏互为反制） |
| 保命 | `min_hp_ratio` / 描述"受到致命伤害时" | 不死 / 坚忍 |
| 免疫 | 面板 `*Immune` | 眩晕/沉默/睡眠/冻结/浮空/缴械/恐惧/麻痹/吸引/传送/束缚 |
| 嘲讽 | `taunt_level` | 转移仇恨 = 团队生存 |
| 治疗输出 | 医疗职业（攻击力/间隔）+ `attack@heal_scale` 每秒型 | 估算口径，已标注 |

### 已知不严谨
- **基础分支特性未建模**：`character_table.trait` 全为 null、`subProfDict` 只有分支名 → 如星熊「阻挡敌人时防御力+20%」这类**基础特性拿不到数据**。因此模组特性里的自身属性加成**也不单方计入**（否则"有模组/无模组"两配置口径不一致），改为在报告里明确标注 ⚠。
- 单敌人压力假设：多敌人集火按线性放大；未计治疗干员支援、地形、阻挡分流
- 闪避按**期望值**折算，实际有方差（高难保命需按最坏情况判断）
- 治疗输出是估算（治疗量与技能叠序有简化）；`heal_scale` 存在"%最大生命"与"攻击力倍率"两种语义，靠描述区分

## 15. 基础分支特性（2026 新增，修正了一处长期数据缺失）

**数据位置（关键，曾踩错）**：分支特性**不在** `character_table[charId].trait`，而在——
| 字段 | 内容 |
|---|---|
| `character_table[charId].description` | **特性文本**（454/454 干员都有，如银灰"可以进行远程攻击，但此时攻击力降低至80%"）|
| `character_table[charId].trait.candidates[].blackboard` | 特性的**数值参数**（仅当特性带数值时非空，151 名干员有）|

> 早期 `build-dataset.mjs` 只读 `c.trait.candidates`，**从不读干员级 `description`** → 454 名干员特性全空。
> 后果举例：**水月本体「拥有50%的物理和法术闪避」被完全漏算**，只有装 Y 模组才显示 65%。
> 修正后：`data/operators.json` 的 `trait` = `{ description, blackboard, ... }`。

### 有效特性（单一数据源）
`tools/modules.mjs: applyModule` 把"基础特性 + 模组特性更新"合成**有效特性**写回 `op.trait`，
下游（④ 生存 / ③ 控制 / 穿透 / 对敌减益）统一读它，不再各自处理：

| 模组字段 | 语义 | 例 |
|---|---|---|
| `additionalDescription` | **追加**到基础特性之上（基础特性仍然生效） | 水月 X 减速光环；星熊 X「阻挡敌人时防御力+20%」 |
| `overrideDescripton` | **覆盖**基础特性（基础特性的效果被替换） | 深蓝之籽把 50% 闪避改成 65%；星熊 Y 把阻挡 3→4 |

> ⚠ 搞混这两者会把水月 Y 的 65% 叠加到基础 50% 上（→ 115%），必须按 `mode` 区分。
> 注：两者在**同一等级内**还会按 `requiredPotentialRank` 出多条候选，需先合并再判定 mode。

### 计入 vs 标注
| 情形 | 处理 |
|---|---|
| 特性提供**闪避/停顿/减速/自回** | ✅ 自动计入（④ 生存 / ③ 控制）：水月 50% 双闪、铃兰 停顿 0.8s@42.1% |
| 特性提供**穿透** | ✅ 自动计入（① 输出）|
| **追加型**自身属性加成 + 条件为**阻挡** | ✅ 计入并标注"按持续阻挡假设"（盾位站岗即常态）：星熊 X 防御 1217→1460 |
| **条件型**自身属性（解放者"技能未开启时攻击力+200%"、阵法术师"通常时防御+200%/法抗+20"）| ⚠ **只标注不计入** —— 按技能开/关两态生效，单一面板无法表达 |
| **条件型**攻击力倍率（领主"远程攻击时攻击力降至80%" → `atk_scale 0.8`）| ⚠ 只标注（依赖站位/距离）|
| **对空/距离/范围内**类条件加成 | ⚠ 只标注 |

标注会以 `【假设与条件】` 块出现在报告里（无模组配置也会出现）——**必须向用户转述**。

## 16. 分支特性"状态"模型（阵法术师 / 解放者，2026 新增）

**为什么单列**：绝大多数分支特性的加成是**无条件常驻**，但有两个分支的特性本身就是"状态开关" ——
用单一面板表达必然算错一边。它们是"以生存换输出"的典型，也是**生存维度权重最高的两类干员之一**。

| 分支 | 常态（技能关闭） | 技能期 |
|---|---|---|
| **阵法术师** `phalanx`（蜜蜡/薄绿/卡涅利安/林/圣聆初雪） | 不攻击；**防御力 ×3、法抗 +20**（生存强） | **加成消失**（生存弱）→ 换群体法术输出 |
| **解放者** `librator`（玛恩纳/龙舌兰/骋风/司霆惊蛰） | **不攻击、阻挡 0**；攻击力蓄力至 **+200%** | **继承蓄力**输出，技能结束时重置；玛恩纳 S3 还有 `trait_up:2`（特性翻倍 → ×5） |

实现：`tools/branch-traits.mjs` —— **按 `subProfessionId` 配置规则**（同分支所有干员自动适用，不是个例补丁）。

### 三处配套口径
1. **④ 生存栏出"常态 / 技能期"双态**（`rule` 命中时强制双态）。蜜蜡实例：
   常态 防御 615/法抗 35 → 对物理·精英可挨 11 击 · 28.6s；技能期 205/15 → 4 击 · 10.4s（**×0.36**）。
   **这个比值就是该分支的取舍代价**，也是它生存权重的真正含义。
2. **常态不攻击 → 平 A 记 0**：`op.idleNoAttack`（`engine/dps-engine.mjs: sustainDps`），
   因此平均 DPS 完全由技能期贡献，覆盖率即输出窗口占比。玛恩纳示例：技能期 11645.8 / 平A 0 / 平均 6521.7。
3. **解放者蓄力在技能期兑现**，按**蓄满假设**计入并标注：
   `攻击力 ×(1 + 特性atk% × 技能trait_up)` —— 玛恩纳 S3 = ×5（需技能未开启约 40s 蓄满）。

### 顺带修掉的一个倍率取值 bug
`atk_scale` 与 `attack@atk_scale` 同时存在时应**优先 `attack@atk_scale`**（"每次攻击的伤害倍率"更具体）。
全库仅 4 个技能两者并存且不同，且描述里的主攻击一律用后者：玛恩纳 S3（1.8 vs 裸 0.12）、
薄绿 S2（1.3 vs 3）、机械师 S3（2.6 vs 3）、断崖 S2（1.0 vs 1.7）。
早期取裸 `atk_scale` 会把**玛恩纳 S3 算成 0.12 倍**（技能期 DPS 41.7 ← 明显异常，是发现该 bug 的线索）。

## 17. 召唤物通道（`summon`，2026 新增）

**为什么单列**：召唤物（凯尔希 Mon3tr、令三形态、麦哲伦无人机、鸿雪"打字机"…）的攻击是**另一条输出线**，
既不能并进本体 `skillDps`，也不能与主力技能简单相加 —— 而且这批干员的**本体技能期常常是"停止攻击"**
（令/麦哲伦的召唤师技能只给召唤物加强化），所以"召唤物 DPS"往往**就是**他们的真实输出。

### 17.1 数据在哪（三条已核实的路径）

| 数据 | 位置 | 说明 |
|---|---|---|
| 召唤物本体 | `character_table` 中 `profession === 'TOKEN'`（**74 条**） | 含面板 `atk/baseAttackTime/blockCnt/maxHp/cost` 与自身技能 |
| 干员↔召唤物关联 | **代号段确定性匹配**：`char_003_kalts` ↔ `token_10002_kalts_mon3tr` | 73/74 命中；唯一未关联的是地图装置 `trap_079_allydonq` |
| ~~`token_table.json`~~ | ❌ **不是召唤物名录** | 只有 4 条 `trap_*` 地图装置 |

产物：`data/summons.json`（引擎可见 73 条：**伤害型 41 / 功能型 8 / 装置 24**）。

### 17.2 三条分类判据（都要，缺一会错）

```
dealsDamage =
  ① 自身技能黑匣子有 >1 的 atk_scale / attack@atk_scale     ← 梅尔6、傀影3、望5.8、温蒂3.5…
  ② 或面板攻击力 > 100                                      ← Mon3tr1402、令弦惊823、乌尔比安777…
  ③ 或人工核对的 atk100 例外（沙之碑/铁钳号/旧日残影/香槟炸弹/矿石杀手）
  且 ∉ NO_DAMAGE_COMBAT（赫默医疗探机 = 治疗无人机，atk125 是**治疗量**）
```

**踩过的坑**：
- **`atk_scale` 是"有则一定是伤害"，但"没有"不代表不是伤害** —— Mon3tr/令/乌尔比安/维什戴尔
  这些纯普攻召唤物**没有倍率键**，早期只按倍率键筛会把最大的几个漏掉。
- **`atk=100 且 间隔=1 且 生命=100` 才是占位装置**（24 条）。只看 `atk=100 && interval=1` 会误杀
  真召唤物：沙之碑 5000 血/阻挡3、铁钳号 6000 血、香槟炸弹 1000 血、迷迭香战术装备 5000 血。
- **`combat` ≠ 有伤害**：治疗/减益型（医疗探机、诅咒娃娃、雷鸣地雷、迷狂牢笼…）面板有 atk 但不打人，
  必须单列 `kind: support`，否则 DPS 被污染。

### 17.3 与 `trap` 通道互斥（防双算）

**陷阱师**（`traper`）的技能 `atk_scale` 已归 **`trap` 通道**（罗宾「夹子」、霜华「迎宾踏垫」、
多萝西「共振装置」、钼铅、望）。这些召唤物**再进 `summon` 通道就是双算** ——
与"陷阱师 atk_scale 误当普攻倍率"是同一类错误。实现里按 id 硬排除（`tools/summon.mjs` 的 `TRAP_CHANNEL_IDS`），
并在 `tools/verify-summons.mjs` 断言两者不同时命中。

### 17.4 三条口径（决定数值倍数，最容易被误用）

1. **独立输出线**：召唤物 DPS 不并入 `skillDps`/`avgDps`；报告单列并明确写"不相加"。
2. **不与本体技能相乘**：召唤物用自己的面板与自己的技能，不套 `skill.attackMult`。
3. **"同时存在数"只认直接证据**（见下）—— 这是最容易造成 2–3 倍误差的地方。

### 17.5 "同时存在数"为什么默认取 1

天赋里的 `cnt`/「可以使用5个」是**总数/携带上限**，**不是**同时在场数：

| 表述 | 实例 | 能否当倍数 |
|---|---|---|
| 「可以使用5个召唤物（**最多同时部署3个**）」 | 令 / 麦哲伦 / 电弧 | ❌ 3 是**干员级总上限**，不是单体倍数 |
| 「可以使用10个（**最多拥有10个**）」 | 多萝西 / 罗宾（库存上限） | ❌ 库存，不是场上数 |
| 「立刻召唤2个魂灵之影（**最多存在3个**，技能结束后保留）」 | 维什戴尔 S3 | ✅ **直接点名该召唤物** |
| 「被击倒时生成一个木偶舞者（**最多存在5个**）」 | 特克诺 | ✅ 直接点名 |

更进一步：**令 / 麦哲伦 / 电弧的召唤物是"技能选择的功能模式"**
（麦哲伦 S2「无人机可部署在近战位，单体法术攻击」/ S3「远程位，群体物理攻击」），
**同一时刻只有 1 种在场** → 取单体数值即为该形态全部输出，**不能把 3 乘上去**。

| 干员 | 处理 | 期望值 |
|---|---|---|
| 凯尔希 | Mon3tr ×1 | 单体 **701.0**（1402/2.0） |
| 令 | 3 种形态取最强（弦惊） | **548.7**（823/1.5） |
| 鸿雪 | "打字机" ×1，限时 25s | **541.3**（866/1.6） |
| 维什戴尔 | 基准 1 个 **777.0**；报告给上限区间 | 最多存在 3 个 → 上限 **2331** |
| 夕 | "小自在" ×1，限时 25s | **209.5**（398/1.9） |
| 温蒂 | 工程蓄水炮 ×1，限时 20s | **243.8**（585/2.4） |

取数实现：`tools/build-summons.mjs` 的 `concurrencyFor()` ——
只采信**同一段文本内**同时出现「最多同时部署/存在/可部署 N 个」与召唤物关键词（或直接点名）的表述；
否则取 1 并在报告标注"保守假设"。

### 17.6 限时寿命的取数位置（一个形状坑）

`attack@tokenduration`（夕「小自在」=25s）在**干员的天赋 `talents[].candidates[].blackboard`** 里，
不在召唤物自身技能里（召唤物技能只有 `skcom_withdraw` = 自我销毁）。
鸿雪「打字机」25s、温蒂蓄水炮 20s **只能在文本里**（`data/summon-semantics.json`，带原文引用）。
**不要用文本里的「持续N秒」兜底**：那是减益/护盾时长（夜烟 抗性-23% 持续1秒、罗比菈塔 护盾 25 秒…），
全库 29 名命中里极少数与召唤物寿命有关，误命中代价远大于收益。

### 17.7 未建模（诚实清单）

- **召唤物自身的技能**：`skillIds` 已记录，但未算。已知会显著改变伤害的有：弦惊「宁作吾」攻速+25%、
  逍遥「笑鸣瑟」4.5 倍、打字机「锐笔速写」2.55 倍、机械水獭「爆破回收」6 倍、虚影「夜幕突袭」3 倍 →
  **当前数值是"仅普攻"的下限**，报告已标注。
- **召唤物自身生存**未进本体 ④ 生存栏（Mon3tr 生命 5433/阻挡3 不在本体承伤里）。
- **铺场时间与部署位成本**：默认按"已在场"。

### 17.8 AI 产物的复核教训（`data/summon-semantics.json`）

召唤物语义层由子代理（LLM 读描述）产出，复核后发现**三类不可信**，因此管线**只采信"限时寿命 + 原文引用"**：

1. `existence` 把**麦哲伦无人机**判成 `skillOnly`，但引用的句子是**电弧的**「技能开启时获得1个召唤物」——
   麦哲伦的无人机是**携带即有、不绑技能**（天赋「功能随技能选择而改变」）。
2. **4 条 `id` 是编造的**：打字机真实 id = `token_10026_bgsnow_subbow`，文件写成 `token_10014_…`；电弧三条同。
   → 故关联**按 `owner|name` 解析，不采信 LLM 给的 id**（与"召唤物关联靠确定性匹配"同一原则）。
3. `concurrency` 给的是干员级总上限（令/电弧=3），不是单体倍数（见 17.5）。

**通用结论**：AI 产物可以提出线索，但**必须按可验证的键去核**；引用与结论不对应的判定一律不采信。

## 18. 召唤物**自身技能**层（2026 新增，§17 的续）

**为什么单列**：召唤物自己有 1–3 个技能，干员的技能可以给召唤物**换技能**
（鸿雪 S3「锐笔速写」→ 打字机 `sktok_bgsnow_3`）。不建模这层，§17 的数值就只是"仅普攻"的下限。

### 18.1 结构事实（已核实，两条反直觉）

1. **不能用召唤物技能序号反推干员技能序号**。令的三种形态（清平/逍遥/弦惊）**共用** `sktok_ling_soul3`，
   形态由"功能"决定而非技能序号 → 只能按**效果**判定，不能按下标对号。
   （`data/summons.json` 里的 `skillIndex` 来自"技能描述点名了该召唤物"，是**溯源标注**，不是映射。）
2. **`2.` 前缀的键属于"第二形态"**。弦惊「宁作吾」的 `2.atk=0.8 / 2.base_attack_time=0.8 / 2.magic_resistance=1`
   是**高级形态**的属性，**不作用于基础形态**；且高级形态的真实强化不在这几个键里 ——
   **硬套会算成"攻击力 −20%、攻速 +25%"的错值**（描述明确写的是"大幅度强化"）→ 必须跳过。

### 18.2 只建模两类（"无条件 + 确实改变普攻"）

| 类型 | 键 | 换算 | 实例 |
|---|---|---|---|
| 攻击力倍率 | `atk`（加成） | ×(1+v) | 衡沙「权知轻重」`atk=0.4` → ×1.4 |
| 攻击力倍率 | `atk_scale` / `attack@atk_scale`（提升至） | ×v | 鸿雪「锐笔速写」`attack@atk_scale=2.55` |
| 攻击间隔 | `attack_speed`（**是百分比不是秒**） | ÷(1+v/100) | 衡沙「上紧发条」`attack_speed=60` → ÷1.6 |
| 攻击间隔 | `base_attack_time`（秒差） | ×(1+v) | 鸿雪「锐笔速写」`base_attack_time=-0.6`（1.6→1.0） |

**认定优先级**：叠层消耗型 > 描述明确"攻击力强化" > 攻速/间隔键 > 否则不计。

**叠层型必须最先判**：傀影「血色乐章」`times=10, atk=0.2`，描述"部署后立即获得10层…（每攻击一次消耗一层）"
→ **全程平均 ×1.2**（不是 ×3.2 的峰值）。它含"部署后立即"，若先跑关键词排除就会被误杀（**踩过**）。

### 18.3 不建模的类型（**不计比硬套更安全**）

| 类型 | 判据 | 条数 | 实例 |
|---|---|---|---|
| 一次性入场/触发伤害 | 描述含 下次攻击/部署后立即/部署时/出现时/触发时/引爆时/开启时/立即对/立即发射/连续攻击 | 18 | 傀影「夜幕突袭」3×、W 2.8×、蜜蜡「沙之碑召唤」3×、温蒂「液氮大炮」3.5× |
| 技能名为效果伤害 | 无描述时看技能名含 爆破/引爆/触发/冲锋/召唤/回收 | 7 | 梅尔「爆破回收」6×（引爆回收）、麦哲伦「回收」、猎潮的骑士「冲锋」2× |

## 19. 召唤物的一次性触发伤害（burst 层，2026 新增）

**为什么单列**：§18 把一次性入场/触发伤害**排除在持续 DPS 之外**（正确），但它是真实输出：
傀影「夜幕突袭」3 倍、W 2.8 倍、蜜蜡「沙之碑召唤」3 倍、温蒂「液氮大炮」3.5 倍…
形态与既有 `burst` 通道一致（**按次结算**），故复用该口径补上。

### 19.1 口径：只报"每次触发"，**不给 DPS**

```
一次性触发伤害（⚠未折入 DPS，按次结算）：爆破回收 每次 2664（物理，atk444 × 6）
          ⚠ 上面"单体 355.2 DPS"（普攻）与"每次 2664"是**两条不同的输出线**：
            触发次数依赖部署位/回收节奏（属玩法层），故不给 DPS —— 与「天下劫」用理想轴同理
```

**为什么不给 DPS**：触发次数取决于部署位、回收/引爆节奏、敌人走位 —— 全是玩法层参数，
描述推导不出。强给一个频率就是把假设伪装成事实（与"天下劫"必须由用户给轴同理）。
用户在软件里可用 `axis` 参数表达自己的节奏。

### 19.2 提取与排除

- 取 `atk_scale`（**不带 `attack@` 前缀**，那是按次/每秒的攻击倍率），值 > 1
- 多次命中（`times`）相乘：钼铅「顽石专用」"造成两次" → `2.5×2`
- **排除周期伤害**（描述含"每秒"）：死芒 S3「怨火缠身」是 DoT，与 burst 形态不同
- **排除概率触发**（描述含"概率"或 bb 有 `prob`）：鸿雪「抑扬格」40% 概率 2.25 倍
- **陷阱类剔除**：罗宾/霜华/多萝西/钼铅/望 已由 `trap`/`burst` 通道结算 → 这里再算就是双算

实测 16 条有触发伤害（陷阱类剔除后）。锚点：梅尔 每次 2664 · 温蒂 2048 · 傀影 1644 · 鸿雁「点题」1992 · 机械师 1800。

### 19.3 一个需要向用户澄清的点

**"单体普攻 DPS"与"每次触发伤害"是两条不同输出线，报告并列但不相加。**
对某些召唤物（W「此面向敌」是爆炸装置、梅尔机械水獭靠引爆回收），
普攻可能**永远打不出来** —— 数据层无法判定"该召唤物是否会进行普攻"，
故**不猜**，只把两条线都列出并标注，由用户结合实际玩法判断。

## 20. 条件型加成与索敌层（`tools/conditional.mjs`，2026 新增）

**定位**：这三类机制**不该进 DPS，但必须让用户看到** —— 与"条件型穿透只标注"同一原则。
`tools/verify-conditional.mjs`（23 断言）保证它们**不污染数值基线**。

### 20.1 对空加成（`atk_scale_to_fly`）

- **全库仅阿罗玛 1 人**（S1「强效清洁」），键值随等级 0.4→0.9，专三 = **90%**
- **语义方向是"加成"不是惩罚**：描述为"对空中敌人**额外**造成相当于攻击力X%的法术伤害"
- **为什么不并进 DPS**：6 个标准场景与 5 档来袭画像**全是地面敌人** → 默认场景下不生效。
  报告给出"空战口径 ≈ 地面 × 1.90"作为参考，但明确标注未计入
- 取数用**已解析的专精等级**取值（`levels[masteryLevel]`），不要"取最大值"（那是碰巧对）

### 20.2 索敌规则（`优先攻击X`）—— 高频通用模式

- **全库 57 名干员**带此表述 → 按"同一表述出现在多个干员身上就进模式库"的判据，属**第一层**
- ⚠ **描述来源必须包含"特性"**：狙击系的「优先攻击空中单位」来自**分支特性**而非技能，
  只在技能描述上跑模式会**漏掉 23 名狙击**（能天使/克洛丝/蓝毒/白金/灰喉…）
- 语义：**不改变 DPS 总量，只改变落点** → 只进报告标注与场景评注，不进输出数值
- 抽取要点：目标描述到标点/`且`为止；文本里的换行是**转义序列 `\n`** 而非真换行（`苦艾` 曾抓成
  `当前生命百分比最低的敌人\n持续时间无限`）

### 20.3 蓄力两态（9 名干员）

卡涅利安 · 龙舌兰 · 温米 · 灵知 · 斥罪 · 薇薇安娜 · 流明 · 焰狐龙梓兰 · 假日威龙陈

- **没有任何公共编码**：有的翻倍（卡涅利安 `atk 0.45→0.6`、`def 0.8→1`）、有的换值（灵知 `atk_scale 1.7→2`、
  `cold 3→4`；龙舌兰 `2.1→2.3`；斥罪 `1.9→2` + 晕眩 `4→5`）、有的延时长/加目标数
- **故做成两态并列展示**（普通形态 → 蓄力形态的强化值 + 原文片段），
  **不自动改动基准 DPS** —— 脱离干员实测硬接参数会算错（§18 的 `2.` 前缀教训同类）
- 蓄力对**操作难度**的影响已由 `tools/difficulty.mjs` 独立计入（"蓄力型：需等待蓄力完成才吃满收益"）

### 20.4 三条"不猜"原则的延续

1. 对空加成不并进地面场景 DPS（**场景不成立就不计**）
2. 索敌不改数值（**只改变落点就不是数值问题**）
3. 蓄力不自动改基准（**没有公共编码就不硬接**）
